## 🧸 The big idea

A program is a recipe that a very fast, very literal cook follows. It works with values, remembers things (state), takes input and produces output, and when it goes wrong you investigate like a detective, not a gambler.

## 🎯 Mastery gate

Reading a lesson is **not** finishing it. Tick every box, honestly:

- [ ] **Explain it:** I can answer every question below out loud, simply, without notes.
  - What is the difference between an expression and a statement? Give three of each.
  - What is "state", and why does it make programs harder to reason about?
  - Why does a syntax error stop a JavaScript file before its first line runs?
  - Describe the scientific method of debugging in five steps.
- [ ] **Implement it:** all exercises are green, and I wrote them without opening solutions first.
- [ ] **Debug it:** I fixed every debugging challenge and can explain *why* each bug happened.
- [ ] **Apply it:** I used this module's ideas in a project or a new program of my own.
- [ ] **Compare alternatives:** I can name another way to solve the same problem.
- [ ] **Identify trade-offs:** I can say when this is the *wrong* tool.
